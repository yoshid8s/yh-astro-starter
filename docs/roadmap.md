# 開発ロードマップ

## 目的

JiJi Style で検証した WordPress Headless CMS + Astro の実装を、他案件にも再利用できる基盤へ整理する。

## フェーズ 1：コンテンツ閲覧体験

### 1. カテゴリーページ

- WordPress REST API からカテゴリ一覧・カテゴリ別記事を取得する
- カテゴリー URL とページネーションの方針を定める
- 記事一覧コンポーネントをトップページと共通化する

**完了条件**：各カテゴリーの一覧を表示でき、記事詳細へ遷移できる。

### 2. パンくずリスト

- トップ、カテゴリ、記事詳細で一貫した階層表示を行う
- JSON-LD の BreadcrumbList も SEO 共通化と合わせて実装する

**完了条件**：表示用パンくずと構造化データが同じ階層情報を使う。

### 3. 関連記事

- 同一カテゴリーを基本に、現在の記事を除いた記事を表示する
- 件数、並び順、不足時の表示ルールを設定で変更可能にする

**完了条件**：記事詳細で関連性のある記事へ自然に回遊できる。

## フェーズ 2：検索・共有の基盤

### 4. SEO 共通化

- title、description、canonical、OGP、Twitter Card を共通コンポーネント化する
- 記事、カテゴリ、固定ページごとの値を型安全に渡せるようにする
- JSON-LD（Article、BreadcrumbList）を段階的に追加する

**完了条件**：各ページ種別で重複のないメタデータを生成できる。

## フェーズ 3：OP / Content Attestation

### 5. OP / CA コンポーネント

- Originator Profile へのリンク・表示コンポーネントをサイト共通部品として設計する
- 記事ごとの Content Attestation 情報を表示できる余地を作る
- 発行・検証処理は表示コンポーネントと分離する

**完了条件**：OP / CA の有無に応じ、記事の信頼情報を一貫して表示できる。

## 実装原則

- WordPress 固有のデータ整形は `src/lib/wordpress/` に集約する
- UI は API のレスポンス形式に直接依存しない
- サイト固有のデザインや文言は設定・テーマ側に寄せる
- 各項目は Issue と Draft PR で小さく検証する
